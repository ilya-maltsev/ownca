# Профили сертификатов

Страница `/cert-profiles/` (пункт меню **Профили сертификатов**) — шаблоны
расширений. Профиль определяет, какие Key Usage, Extended Key Usage и поля
из реестра OID попадут в выпускаемый сертификат.

Профили **общие** и не привязаны к конкретному УЦ: в форме выпуска любой
профиль можно использовать с любым УЦ.

## Список профилей

| Столбец | Содержимое |
|---|---|
| Имя | Внутренний идентификатор: строчные латинские буквы, цифры и `_`. |
| Отображаемое имя | Название профиля в интерфейсе. |
| Описание | Произвольный текст. |
| Key Usage | Краткая запись битов Key Usage, например `dS, kE`. |
| Extended Key Usage | Список EKU. |
| CA | Отметка `CA`, если профиль предназначен для сертификатов УЦ (basicConstraints CA:TRUE). |
| Используется | Сколько выпущенных сертификатов ссылается на профиль. Второе число всегда равно 0: оно осталось от очереди заявок, которой в OwnCA больше нет. |

## Содержимое профиля

### Key Usage

Набор битов, определяющих допустимые операции с ключом:

* `digitalSignature` — электронная подпись (установка соединения TLS,
  подпись данных);
* `nonRepudiation` (`contentCommitment`) — подпись, от которой владелец не
  может отказаться (юридически значимая);
* `keyEncipherment` — шифрование симметричного ключа;
* `dataEncipherment` — шифрование данных непосредственно открытым ключом;
* `keyAgreement` — выработка общего ключа (DH, ECDH, VKO);
* `keyCertSign` — подпись сертификатов (только для УЦ);
* `cRLSign` — подпись CRL;
* `encipherOnly` / `decipherOnly` — уточнения к `keyAgreement`.

Подробнее — в разделе [Key Usage и Extended Key Usage](key_usage.md).

### Extended Key Usage

Список OID, определяющих назначение сертификата. Наиболее частые:

| OID | Назначение |
|---|---|
| `1.3.6.1.5.5.7.3.1` | Аутентификация сервера TLS |
| `1.3.6.1.5.5.7.3.2` | Аутентификация клиента TLS |
| `1.3.6.1.5.5.7.3.3` | Подпись кода |
| `1.3.6.1.5.5.7.3.4` | Защита электронной почты (S/MIME) |
| `1.3.6.1.5.5.7.3.8` | Метки времени |
| `1.3.6.1.5.5.7.3.9` | Подпись ответов OCSP |

### Поля из реестра OID

К профилю можно подключить поля из реестра OID. Каждое поле — это атрибут
Subject DN, элемент SAN или отдельное расширение; значение вводится при
выпуске.

### Прочие параметры

| Параметр | Описание |
|---|---|
| Профиль УЦ | Если включён, в сертификат добавляется `basicConstraints = CA:TRUE` — для сертификатов подчинённых УЦ. |
| Дополнительные расширения | Строки расширений в формате OpenSSL, которые добавляются в сертификат без изменений. |

## Копирование профиля

На странице редактирования профиля рядом с кнопкой **Удалить** есть кнопка
**Копировать**. Она создаёт полную копию профиля (вместе с подключёнными
полями из реестра OID) под новым именем и открывает её для
редактирования. Так удобно создавать вариант существующего профиля.

## Профили и УЦ на CryptoPro CSP

УЦ на CryptoPro поддерживает не все расширения X.509. Такой УЦ не выпустит
сертификат по профилю, в котором есть `nameConstraints`,
`policyConstraints`, `inhibitAnyPolicy`, `certificatePolicies`, строки из
поля «Дополнительные расширения», поля реестра OID с размещением
«Extension» или `otherName` в SAN.

При включённом CryptoPro редактор профиля сворачивает соответствующие
разделы («Ограничения имён», «Policy Constraints», «Дополнительные
расширения») и помечает их: поля можно редактировать, но они не на виду.
Вверху редактора выводится перечень того, что УЦ на CryptoPro отклонит, а
в форме выпуска такой профиль помечен в списке. Подробнее — в разделе
[Криптопровайдер CryptoPro CSP](cryptopro.md).

Раздел полей из реестра OID не сворачивается: размещения SAN DNS, IP,
email и URI на CryptoPro работают, не поддерживаются только «Extension» и
«SAN otherName».
