# Управление УЦ

Страница `/cas/` (пункт меню **Центры сертификации**) — корневые и
подчинённые удостоверяющие центры. На ней находятся форма
**Создать новый центр сертификации** и список УЦ.

## Список УЦ

| Столбец | Содержимое |
|---|---|
| Имя | Внутреннее имя УЦ, используется в адресах страниц и в интерфейсе. |
| Тип | Корневой или промежуточный (подчинённый) УЦ. |
| Родитель | Родительский УЦ (для подчинённого). |
| Алгоритм | Алгоритм ключа. |
| Выпущено | Сколько сертификатов выпущено. |
| Действителен до | Окончание срока действия сертификата УЦ. |
| Статус | Активен или отключён. |

## Создание УЦ

Форма создания расположена над списком и видна всегда. Возможны два
случая:

1. **Корневой УЦ** — создаётся самоподписанный сертификат.
2. **Промежуточный УЦ** — выберите этот тип, и появится поле
   **Родительский УЦ**. OwnCA создаёт запрос, подписывает его
   родительским УЦ и сохраняет цепочку.

### Поля формы

| Поле | Назначение |
|---|---|
| Имя * | Внутреннее имя УЦ. |
| Общее имя (CN) * | CN в Subject DN УЦ. |
| Тип | Корневой или промежуточный УЦ. |
| Родительский УЦ | Обязательно для промежуточного УЦ. |
| Алгоритм | `gost2012_256`, `gost2012_512`, `rsa:2048`, `rsa:4096`, `ec:P-256`, `ec:P-384`, `ed25519`. Алгоритм определяет **семейство ключей** УЦ (`gost`, `rsa`, `ec`, `ed25519`), а значит, и то, какие конечные сертификаты он сможет подписывать (см. [Выпуск сертификата](custom_cert_issue.md)). Для промежуточного УЦ доступны только алгоритмы семейства родительского: его сертификат подписывает родительский УЦ, поэтому ГОСТ и RSA в одной цепочке не смешиваются. |
| Срок действия (дней) | По умолчанию — `OWNCA_DEFAULT_CA_DAYS`. |
| Длина цепочки (pathlen) | Сколько уровней подчинённых УЦ допускается ниже этого УЦ; если не заполнено, ограничения нет. |
| URL точки распространения CRL | Адрес CRL, который записывается в выпускаемые сертификаты. |
| URL сертификата издателя (AIA) | Где можно скачать сертификат этого УЦ. |
| URL OCSP-респондера | Адрес службы OCSP. |
| URL репозитория (SIA) | Адрес хранилища сертификатов УЦ (в основном для подчинённых УЦ). |
| URL дельта-CRL | Адрес разностного CRL. |
| Альтернативные имена издателя | По одной записи в формате OpenSSL в строке, например `email:ca@example.org`. |
| Страна / Регион / Город / Организация / Подразделение | Дополнительные атрибуты Subject DN. |

Как сочетаются адреса из УЦ и из профиля, описано в разделе
[Точки распространения](distribution_points.md).

## Импорт существующего УЦ

Форма **Импорт существующего УЦ** (под формой создания) добавляет в OwnCA
УЦ, созданный в другой системе, чтобы выпускать сертификаты от его имени.
Укажите **сертификат УЦ и его закрытый ключ** — двумя файлами (или блоками
PEM) либо одним файлом **PKCS#12 (`.pfx`, `.p12`)**, в котором есть и то,
и другое. OwnCA проверяет их соответствие, создаёт на диске каталог УЦ, и
УЦ сразу можно использовать для выпуска сертификатов и CRL.

| Поле | Назначение |
|---|---|
| Имя * | Внутреннее имя импортируемого УЦ. |
| Сертификат УЦ (PEM/DER) | Файл или текст сертификата. Сертификат должен содержать `basicConstraints CA:TRUE`. |
| Закрытый ключ УЦ (PEM/DER) | Обязателен: импортированный УЦ должен подписывать сертификаты. |
| Файл PKCS#12 | Файл `.pfx` или `.p12` с сертификатом **и** ключом. Если он указан, поля сертификата и ключа не учитываются; импортируется только сертификат, ключ которого есть в файле (остальные сертификаты цепочки пропускаются). |
| Пароль ключа / PKCS#12 (если зашифрован) | Указывается, только если ключ или файл защищены паролем. |
| Родительский УЦ (необязательно) | Для подчинённого УЦ — родительский УЦ, уже добавленный в OwnCA (нужен для построения цепочки). Родительский УЦ должен быть того же семейства ключей: УЦ с ключом ГОСТ не мог выпустить сертификат с ключом RSA. Если настоящего издателя в OwnCA нет, оставьте поле пустым. |

При импорте OwnCA автоматически **определяет алгоритм ключа** по
сертификату (ГОСТ 256/512, RSA, EC P-256/P-384, Ed25519) и **тип УЦ**
(самоподписанный сертификат — корневой, иначе подчинённый), а также
**проверяет**, что это сертификат УЦ и что ключ ему соответствует. Ключ от
другого сертификата или сертификат, не являющийся сертификатом УЦ,
отклоняются. Файлы PKCS#12, зашифрованные устаревшими алгоритмами (RC2-40,
3DES — например, выгруженные из Windows), открываются автоматически.
Алгоритм ключа должен быть разрешён в режимах выпуска.

Семейство ключа определяется **по открытому ключу сертификата из файла**,
а не по типу контейнера, в который попал ключ: при импорте через CryptoPro
файл с ключом не по ГОСТ отклоняется. Иначе появился бы УЦ, который
числится ГОСТ-УЦ и предлагает ГОСТ-алгоритмы, но имеет ключ RSA.

## Страница УЦ

На странице `/cas/<uuid>/`:

* кнопки **Скачать сертификат УЦ**, **Скачать CRL**, **Экспорт PKCS#12**,
  **Перегенерировать CRL**, **Удалить**;
* блок **Параметры центра сертификации** — все сведения об УЦ, в том числе
  текущий номер CRL, адреса точек распространения и число выпущенных
  сертификатов, действующих и отозванных;
* блок **Точки распространения** — форма для изменения `crl_url`,
  `aia_url`, `ocsp_url`, `sia_url`, `freshest_crl_url` и `issuerAltName`
  после создания УЦ. Изменения действуют для сертификатов, выпущенных
  после сохранения;
* полный текст сертификата УЦ (вывод `openssl x509 -text`).

### Кнопки

* **Скачать сертификат УЦ** — файл PEM с сертификатом УЦ.
* **Экспорт PKCS#12** — сертификат и ключ УЦ в защищённом паролем файле
  `.p12` (см. ниже).
* **Перегенерировать CRL** — выпускает новый CRL и добавляет запись в
  журнал выпусков CRL.
* **Скачать CRL** — последний CRL; если CRL ещё не выпускался, он
  выпускается при скачивании.
* **Удалить** — удаление возможно, только если у УЦ **нет подчинённых УЦ и
  ни одного выпущенного сертификата**. Отозванные и просроченные
  сертификаты тоже учитываются — сначала удалите их.

У УЦ на CryptoPro CSP рядом с кнопкой удаления есть флажок
**Удалить и ключевой контейнер**, по умолчанию **снятый**. Закрытый ключ
хранится в хранилище CryptoPro, вне тома с данными, и при удалении
каталога УЦ сам по себе не удаляется.

* **Флажок снят** — контейнер остаётся в хранилище CryptoPro. Сведения о
  том, какому УЦ он принадлежал, хранились в удалённом каталоге, поэтому
  найти контейнер потом можно только по имени.
* **Флажок установлен** — контейнер удаляется вместе с каталогом. Это
  необратимо: ключ нельзя извлечь, резервная копия каталога данных его не
  вернёт, и выпускать CRL для сертификатов этого УЦ станет нечем. Окно
  подтверждения об этом предупреждает.

Такой же флажок есть на странице сертификата, если его ключ создан на
сервере (у сертификата, выпущенного по внешнему запросу, своего
контейнера нет). Если тот же контейнер использует продлённый сертификат
(при продлении ключ не меняется), контейнер удаляется только вместе с
последним сертификатом, который его использует, — даже при установленном
флажке.

Если создание **не удалось** (ошибка при создании УЦ, отклонённый импорт,
прерванный выпуск), контейнер удаляется всегда и без вопросов: УЦ или
сертификат, которому он предназначался, так и не появился.

### Выгрузка УЦ в PKCS#12

**Экспорт PKCS#12** сохраняет сертификат и закрытый ключ УЦ в один
защищённый паролем файл `.p12` (PFX) — это действие, обратное импорту.
Задайте пароль, выберите шифрование и, для подчинённого УЦ, при
необходимости отметьте **Включить цепочку**, чтобы добавить сертификаты
родительских УЦ.

| Шифрование | Шифр / контрольная сумма | Для каких программ |
|---|---|---|
| Стандартный (AES-256, совместимый) | AES-256-CBC, SHA-256 | Для любых современных программ. |
| ГОСТ Кузнечик — ТК-26 (RFC 9548) | `kuznyechik-ctr-acpkm` / `md_gost12_512` | Для современных программ с поддержкой ГОСТ. |
| ГОСТ Магма — ТК-26 (RFC 9548) | `magma-ctr-acpkm-omac` / `md_gost12_256` | То же, на шифре Магма. |
| ГОСТ 28147-89 (устаревший) | `gost89` / `md_gost94` | Для старых программ без поддержки ТК 26. |

Файлы с ГОСТ-шифрованием формирует gost-engine; программа, в которую вы их
импортируете, должна поддерживать соответствующий формат. Закрытый ключ
покидает сервер внутри файла — храните файл так же бережно, как сам ключ.

## CRL

CRL выпускается заново при отзыве любого сертификата этого УЦ, а также по
кнопке **Перегенерировать CRL**. Каждый выпуск записывается в журнал.
Подробнее — в разделе [Отзыв и CRL](cert_revoke.md).

## Хранение ключей

Закрытые ключи УЦ на OpenSSL хранятся в каталоге `OWNCA_STORAGE_DIR` (по
умолчанию `/var/lib/ownca/`), ключи УЦ на CryptoPro — в контейнерах
CryptoPro (`/var/opt/cprocsp/keys`). Резервные копии делайте одновременно
для обоих мест.

> **Криптопровайдер УЦ изменить нельзя.** При включённом CryptoPro CSP новый
> ГОСТ-УЦ создаётся на CryptoPro, и его ключ навсегда остаётся в контейнере.
> Ограничения такого УЦ описаны в разделе
> [Криптопровайдер CryptoPro CSP](cryptopro.md).
