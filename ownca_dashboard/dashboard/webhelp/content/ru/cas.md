# Управление УЦ

`/cas/` — корневые и подчинённые удостоверяющие центры. На странице
совмещены встроенная форма **Create new authority** и список УЦ.

## Список УЦ

| Колонка | Описание |
|---|---|
| Name | Внутреннее имя (используется в URL и интерфейсе). |
| Type | `Root CA` / `Intermediate CA`. |
| Parent | Родительский УЦ (для intermediate). |
| Algorithm | Алгоритм ключа. |
| Issued | Сколько сертификатов выпущено. |
| Valid Until | `notAfter` сертификата УЦ. |
| Status | `Active` (когда `is_enabled`) или `Disabled`. |

## Создание УЦ

Форма **Create new authority** размещена над таблицей — отдельной
кнопки «открыть форму» нет, она показана всегда. Два сценария:

1. **Root CA** — создаётся самоподписанный сертификат.
2. **Intermediate CA** — выберите **Type = Intermediate CA**, после
   чего появится поле **Parent CA**; OwnCA генерирует CSR,
   подписывает его родителем и сохраняет цепочку.

### Поля формы

| Поле | Назначение |
|---|---|
| Name * | Внутренний идентификатор (URL и интерфейс). |
| Common Name * | CN из subject DN УЦ. |
| Type | `Root CA` или `Intermediate CA`. |
| Parent CA | Обязательно при Type = Intermediate. |
| Algorithm | `gost2012_256`, `gost2012_512`, `rsa:2048`, `rsa:4096`, `ec:P-256`, `ec:P-384`, `ed25519`. Алгоритм УЦ задаёт его **семейство ключа** (`gost`, `rsa`, `ec`, `ed25519`) и тем самым определяет, какие листовые сертификаты он сможет подписывать — см. [Custom Cert Issue](custom_cert_issue.md). При Type = Intermediate список сужается до семейства выбранного родителя: родитель подписывает сертификат подчинённого УЦ, поэтому ГОСТ и RSA в одной цепочке не смешиваются. |
| Validity (days) | Срок действия УЦ; по умолчанию `OWNCA_DEFAULT_CA_DAYS`. |
| Path length | Максимальная глубина цепочки под этим УЦ (пусто = без ограничения). |
| CRL Distribution Point URL | CDP, встраиваемый в выпускаемые сертификаты. |
| AIA caIssuers URL | Где скачать сертификат данного УЦ. |
| OCSP responder URL | OCSP-адрес. |
| SIA caRepository URL | Subject Information Access (актуально для sub-CA). |
| Freshest CRL URL | Адрес delta-CRL. |
| issuerAltName entries | По одной openssl-записи в строке (например, `email:ca@example.org`). |
| Country / State / Locality / Organization / Unit | Дополнительные атрибуты subject DN. |

Правила приоритета между значениями УЦ и переопределениями профиля —
см. [Точки распространения](distribution_points.md).

## Импорт существующего УЦ

Форма **Import existing authority** (под формой создания) регистрирует
УЦ, созданный во внешней системе, чтобы OwnCA мог подписывать им
сертификаты. Укажите **сертификат УЦ и соответствующий закрытый ключ** —
либо двумя отдельными файлами/блоками PEM, либо одним контейнером
**PKCS#12 (`.pfx` / `.p12`)**, содержащим и то, и другое. OwnCA проверяет
пару, разворачивает на диске каталог УЦ, и центр сразу готов к выпуску
сертификатов и генерации CRL.

| Поле | Назначение |
|---|---|
| Name * | Внутреннее имя импортируемого УЦ. |
| Сертификат | Сертификат УЦ, **PEM или DER** (загрузка файла или вставка текста). Должен содержать `basicConstraints CA:TRUE`. |
| Закрытый ключ | Соответствующий закрытый ключ УЦ, **PEM или DER**. Обязателен — импортируемый УЦ является *подписывающим*. |
| Контейнер PKCS#12 | Файл `.pfx` / `.p12`, содержащий сертификат **и** закрытый ключ. При загрузке **заменяет** отдельные поля сертификата/ключа; импортируется только сертификат, ключ которого лежит в контейнере (лишние сертификаты цепочки игнорируются). |
| Пароль ключа / PKCS#12 | Пароль, защищающий закрытый ключ или контейнер PKCS#12. Указывается, только если материал зашифрован. |
| Parent CA | Необязательно. Для импортируемого intermediate связывает его с родителем, уже имеющимся в OwnCA (для построения цепочки). Родитель должен быть того же семейства ключей, что и импортируемый сертификат: УЦ на ГОСТ не мог выпустить RSA-сертификат. Если настоящий издатель в OwnCA не зарегистрирован, оставьте поле пустым. |

При импорте OwnCA автоматически **определяет алгоритм ключа** по
сертификату (ГОСТ 256/512, RSA, EC P-256/P-384, Ed25519), **определяет
тип** (самоподписанный сертификат сохраняется как root, иначе
intermediate) и **проверяет**, что сертификат является УЦ и что закрытый
ключ ему соответствует — несоответствующий или не-CA материал
отклоняется. Контейнеры PKCS#12, запечатанные устаревшими шифрами
(RC2-40 / 3DES, например экспортированные из Windows), читаются через
legacy-провайдер OpenSSL автоматически. Алгоритм импортированного ключа
должен быть разрешён текущими настройками режима выпуска.

Семейство ключа определяется **по открытому ключу сертификата из
контейнера**, а не по типу провайдера, в который лёг ключ: контейнер с
не-ГОСТ ключом отклоняется на пути импорта через CryptoPro, а не
записывается как ГОСТ-УЦ. Иначе получился бы УЦ, заявляющий ГОСТ и
предлагающий ГОСТ-алгоритмы для RSA-ключа.

## Страница УЦ

`/cas/<uuid>/` содержит:

* Панель кнопок: **Download CA cert**, **Download CRL**,
  **Regenerate CRL**, **Delete**.
* Панель **Authority details** — все поля УЦ, включая текущий номер
  CRL, все URL точек распространения и счётчик выпущенных
  сертификатов с разбивкой active / revoked.
* Панель **Distribution points** — форма для редактирования
  `crl_url`, `aia_url`, `ocsp_url`, `sia_url`, `freshest_crl_url` и
  `issuerAltName` уже после создания УЦ. Изменения применяются к
  сертификатам, выпускаемым с этого момента.
* Полный вывод `openssl x509 -text` для сертификата УЦ.

### Кнопки на странице УЦ

* **Download CA cert** — PEM-файл сертификата УЦ.
* **Export PKCS#12** — упаковать сертификат и ключ УЦ в защищённый
  паролем `.p12`; см. ниже.
* **Regenerate CRL** — создаёт новый CRL и добавляет запись в
  журнал выпусков CRL.
* **Download CRL** — отдаёт последний CRL (генерирует новый, если
  ещё не было ни одного).
* **Delete** — срабатывает только когда у УЦ **нет дочерних УЦ и
  нет ни одного выпущенного сертификата**. Отозванные и истёкшие
  сертификаты тоже считаются — их нужно удалить заранее.

У УЦ на CryptoPro CSP рядом с кнопкой появляется флажок **Удалить и
ключевой контейнер**, по умолчанию **выключенный**. Закрытый ключ лежит
в хранилище провайдера, вне тома с данными, поэтому удаление каталога
само по себе его не трогает.

* **Флажок снят** — контейнер остаётся в хранилище провайдера. Ссылаться
  на него больше нечему: привязка к УЦ жила в удалённом каталоге, так
  что найти его можно только по имени.
* **Флажок установлен** — контейнер удаляется вместе с каталогом.
  Необратимо: ключ неизвлекаем, и резервная копия каталога данных его не
  вернёт, а выпустить CRL по ранее подписанным этим УЦ сертификатам
  будет уже нечем. Подтверждение прямо об этом предупреждает.

Тот же флажок есть на странице сертификата, если его ключ был
сгенерирован на сервере (у сертификата по внешнему CSR своего контейнера
нет). Контейнер, на который ссылается ещё и продлённый сертификат
(продление переиспользует тот же ключ), сохраняется до удаления
последней ссылки, флажок этого не отменяет.

При **откате неудавшегося создания** — упавшая генерация УЦ, отклонённый
импорт, несостоявшийся выпуск — контейнер удаляется всегда и без
вопросов: записи, которой он мог бы принадлежать, не появилось.

### Экспорт УЦ в PKCS#12

**Export PKCS#12** упаковывает собственный сертификат и закрытый ключ УЦ
в один защищённый паролем файл `.p12` (PFX) — обратная операция к
разделу **Импорт существующего УЦ** выше. Задайте пароль, выберите
**набор** алгоритмов шифрования контейнера / MAC и (для intermediate)
при необходимости отметьте **Include chain**, чтобы добавить сертификаты
родительских УЦ.

| Набор | PBE / MAC | Для чего |
|---|---|---|
| Standard (AES-256) | контейнеры AES-256-CBC, MAC SHA-256 | Совместимый вариант по умолчанию — любой современный ридер PKCS#12. |
| GOST Kuznyechik | `kuznyechik-ctr-acpkm` / `md_gost12_512` | TK-26 (RFC 9337 / 9548) — современное ГОСТ-ПО. |
| GOST Magma | `magma-ctr-acpkm-omac` / `md_gost12_256` | TK-26, вариант на Magma. |
| GOST 28147-89 (legacy) | `gost89` / `md_gost94` | Устаревшие инструменты (эпохи CryptoPro) до TK-26. |

ГОСТ-наборы формируются встроенным gost-engine и требуют, чтобы
импортирующее ПО понимало соответствующий формат PKCS#12 по ГОСТ.
Закрытый ключ покидает сервер внутри экспортируемого файла — обращайтесь
с ним так же бережно, как с ключом на диске.

## CRL

CRL автоматически перегенерируется при отзыве любого сертификата
этого УЦ, а также по нажатию **Regenerate CRL**. Каждая генерация
фиксируется записью `CrlExport`. Подробно — в разделе [Отзыв и
CRL](cert_revoke.md).

## Безопасность ключей

Закрытые ключи УЦ хранятся в каталоге `OWNCA_STORAGE_DIR` (по
умолчанию `/var/lib/ownca/`). Резервное копирование этого каталога —
обязательно.

> **Выбор криптопровайдера необратим.** При включённом CryptoPro CSP новый ГОСТ-УЦ
> создаётся на сертифицированном провайдере, и его ключ навсегда остаётся в
> контейнере. Ограничения такого УЦ —
> [Криптопровайдер CryptoPro CSP](cryptopro.md).
