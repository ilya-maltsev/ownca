# Обслуживание

Страница `/system/maintenance/` (пункт меню **Обслуживание**): счётчики,
состояние криптопровайдера и служебные действия.

## Счётчики

Значения берутся непосредственно из базы данных:

* число УЦ;
* число действующих сертификатов;
* число отозванных сертификатов;
* число просроченных сертификатов;
* сколько раз выпускались CRL (по всем УЦ).

## Криптопровайдер

Блок показывает, исправна ли криптографическая часть OwnCA:

* **ГОСТ-движок загружен** — зелёная отметка, если команда
  `openssl engine gost` выполняется успешно, иначе красная. Пока отметка
  красная, работают только RSA, ECDSA и Ed25519.
* **Каталог хранения** — значение `OWNCA_STORAGE_DIR`.
* **Версия openssl** — полный вывод `openssl version -a` (параметры
  сборки, платформа, каталог модулей).

## Блоки CryptoPro CSP

Если CryptoPro установлен в образ, на странице также показываются блоки
**Статус провайдера**, **Гамма ДСЧ** и **Лицензия**. Когда CryptoPro
включён, блок «Криптопровайдер» скрывается: ГОСТ-подпись выполняет
CryptoPro, а не OpenSSL. Подробнее — в разделе
[Криптопровайдер CryptoPro CSP](cryptopro.md).

## Операции

В блоке **Операции** собраны служебные действия; результат каждого
выводится рядом с его кнопкой.

### Обновить метаданные

Заново читает с диска все файлы сертификатов и обновляет сведения в базе
данных (владелец, сроки, отпечаток, серийный номер). Кроме того, все
действующие сертификаты с истёкшим сроком переводятся в состояние
«просрочен».

Используйте после ручного изменения файлов в каталоге хранения. Файлы на
диске при этом **не** изменяются.

### Перестроить все CRL

Заново выпускает CRL для каждого включённого УЦ и добавляет запись в
журнал выпусков CRL. Номер каждого CRL увеличивается, в список попадают
все отозванные на этот момент сертификаты.

Каждый выпущенный CRL также записывается в общий каталог
`OWNCA_STORAGE_DIR/crls/` под именем `<имя_УЦ>.crl` (например,
`rsa_root.crl`), чтобы все CRL можно было публиковать из одного места.
Основная копия CRL каждого УЦ по-прежнему хранится в `cas/<uuid>/crl.pem`.

Используйте после массового отзыва, а также чтобы продлить срок действия
CRL (`nextUpdate`): по расписанию OwnCA их не перевыпускает, поэтому
делайте это до истечения текущих CRL.
